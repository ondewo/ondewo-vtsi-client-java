## Release ONDEWO VTSI Java Client 9.0.0

### Breaking Changes

* `AsteriskConfigsFiles.sip_conf_file_string` is renamed to `pjsip_conf_file_string` in ondewo-vtsi-api 9.0.0,
  so the generated accessors move:

  | 8.7.x | 9.0.0 |
  | --- | --- |
  | `getSipConfFileString()` / `getSipConfFileStringBytes()` | `getPjsipConfFileString()` / `getPjsipConfFileStringBytes()` |
  | `setSipConfFileString(...)` / `setSipConfFileStringBytes(...)` / `clearSipConfFileString()` | `setPjsipConfFileString(...)` / `setPjsipConfFileStringBytes(...)` / `clearPjsipConfFileString()` |
  | `AsteriskConfigsFiles.SIP_CONF_FILE_STRING_FIELD_NUMBER` | `PJSIP_CONF_FILE_STRING_FIELD_NUMBER` |

  **Migration:** rename the calls; nothing else changes. Field number 1 and type `string` are kept, so the
  change is wire-compatible in both directions. The protobuf JSON key moves from `sipConfFileString` to
  `pjsipConfFileString` (no `json_name` override), so JSON produced or parsed with `JsonFormat` must move too.
* Eleven `calls.proto` scalars gained explicit presence (`optional`):
  `InterruptionHandlingConfig.transcribe_on_disabled_interruptions`,
  `TurnDetectionConfig.turn_detection_system_prompt` / `turn_detection_user_prompt`,
  `AudioObjectStorageConfig.activate_audio_object_storage`,
  `AudioObjectStorageServicesActivationConfig.activate_s2t` / `activate_t2s`,
  `MessageBrokerConfig.activate_message_broker` and
  `MessageBrokerServicesActivationConfig.activate_s2t` / `activate_nlu` / `activate_t2s` / `activate_sip`.
  In Java the existing getters and setters stay; each field gains `hasX()` / `clearX()`, and an explicitly set
  default value (e.g. `false`) is now sent on the wire. **Migration:** none for code that compiles against 8.7.x;
  use `hasX()` where "not set" must be told apart from the default.

### New Features

* Tracks API Version [9.0.0](https://github.com/ondewo/ondewo-vtsi-api/releases/tag/9.0.0) (vendoring
  ondewo-sip-api 5.5.0; nlu 7.1.0, s2t 7.5.0 and t2s 6.6.0 unchanged). New in the API (summary of its release
  notes):
  * New service `ondewo.vtsi.Softphones` (`SoftphonesGrpc`, `softphones.proto`): softphone SIP accounts with
    their own credentials, client certificates and provisioning; secrets are returned only by
    `CreateSoftphoneAccount` and `RotateSoftphoneCredentials`.
  * New service `ondewo.vtsi.Campaigns` (`CampaignsGrpc`, `campaigns.proto`): outbound call campaigns with
    `max_parallel_calls`, retries, lifecycle (start / stop / hard stop / resume), statistics, campaign calls
    and the server stream `StreamCampaignStatus`.
  * New service `ondewo.vtsi.Events` (`EventsGrpc`, `events.proto`): the `VtsiEvent` catalogue, event
    subscriptions, webhooks (custom header values are write-only) and the server stream `SubscribeVtsiEvents`.
  * `Calls`: `AddCallersToCampaign` / `AddScheduledCallersToCampaign`, the status streams
    `StreamCallerStatus` / `StreamListenerStatus` / `StreamScheduledCallerStatus`, call control
    (`InviteToCall`, `RemoveCallParticipant`, `SetCallMediaControl`, bidirectional `StreamCallAudio`,
    server-streaming `ListenCallAudio`), typed transfers (`CallTarget`, `TransferMode`, `TransferOutcome`),
    `idempotency_key` on the five batch-creating requests, and answering machine detection
    (`AnsweringMachineDetectionConfig`, `Call.redial_recommended` / `redial_reason` /
    `answering_machine_detection_end_description`).
  * `AsteriskConfigsVariables`: `sip_trunk_transport`, `sip_trunk_source_cidr`, `sip_trunk_ca_certificates_pem`,
    `sip_trunk_verify_server` and `softphone_permit_cidrs`; `VtsiProject.transfer_phone_number_allowlist`.
  * The supervision rpcs (`InviteToCall`, `SetCallMediaControl`, `StreamCallAudio`, `ListenCallAudio`,
    `TransferCall` / `TransferCalls`) require `PROJECT_DEVELOPER` or higher and the auth mode `ENFORCE` on the
    server; see the API release notes for the rolling-update behaviour of the new rpcs.
* The three new services share the channel built by `GrpcChannels.newChannel(config)` like every other stub of
  this client; no hand-written wrapper changes were needed.
* The vendored `ondewo.sip` stubs are regenerated from ondewo-sip-api 5.5.0 and identical to those of
  ondewo-sip-client-java 5.5.0. Do not mix this client with an ondewo-sip-client-java older than 5.5.0 on one
  classpath: both ship the `ondewo.sip` classes.

### Improvements

* The stubs are generated by the [ONDEWO proto compiler](https://github.com/ondewo/ondewo-proto-compiler)
  `5.15.5` (was `5.15.2`; no change to the java image between the two).

### Tests

* `GeneratedServicesTest`: 26 generated services (was 23); `Softphones`, `Campaigns` and `Events` carry their
  proto names, the new streaming rpcs their method types, and a unary call on each new service runs over the
  in-process transport; all stub flavours of the new services build.
* `GeneratedMessagesTest`: `pjsip_conf_file_string` is field 1 and decodes bytes written for the old name; a
  scalar that gained `optional` keeps explicit presence.

## Release ONDEWO VTSI Java Client 8.7.1

### New Features

* TLS and mutual TLS helper in the hand-written package `com.ondewo.vtsi.channel` (kept by a
  regeneration): `ClientConfig` (`host`, `port`, `grpcCert`, `grpcClientCert`, `grpcClientKey`,
  `useSecureChannel`, default `true`) and `GrpcChannels.newChannel(config)` /
  `GrpcChannels.newChannelBuilder(config)`. One channel serves every stub of the client.
  * The certificate fields take **PEM content, not file paths**. Non-PEM material (typically a path) or an
    encrypted / non-PKCS#8 key is refused with `IllegalArgumentException` before any connection is
    attempted. An empty `grpcCert` means the JVM trust store.
  * `grpcClientCert` and `grpcClientKey` are both-or-neither: setting only one makes
    `ClientConfig.Builder.build()` throw. Both empty means plain server-authenticated TLS.
  * `useSecureChannel(false)` with a client identity throws instead of silently dropping it. A plaintext
    channel logs a `WARNING` naming `host:port` through `java.util.logging`; the logging configuration of
    the application is never touched.
  * `ClientConfig.toString()` shows `grpcClientKey` as `***REDACTED***` (empty when unset) and the
    certificates only as their length; no error message renders a PEM, the key or a whole config.
  * A bare IPv6 literal host is bracketed (`::1` -> `[::1]:50051`); PEMs with CRLF line endings work.
* Channel defaults aligned with the ONDEWO Python clients where grpc-java exposes them: keepalive timeout
  20 s, `keepAliveWithoutCalls(false)`, `maxInboundMessageSize(Integer.MAX_VALUE)`.
  * Keepalive time is **5 minutes**, not the Python clients' 30 s: grpc-java has no
    `http2.max_pings_without_data`, so a 30 s ping on a silent stream is answered by a default grpc-core
    server with a `too_many_pings` GOAWAY (measured against a grpcio 1.81 server). Pair a server that
    permits faster pings with a shorter `keepAliveTime` on the builder.
  * Not available in grpc-java and documented as gaps: `http2.max_pings_without_data`,
    `max_reconnect_backoff_ms` (grpc-java's backoff caps at 120 s), and no retry policy is configured
    (only gRPC's transparent retries).

### Improvements

* Still tracking API Version [8.7.0](https://github.com/ondewo/ondewo-vtsi-api/releases/tag/8.7.0)
* The stubs are generated by the [ONDEWO proto compiler](https://github.com/ondewo/ondewo-proto-compiler) `5.15.2` (was `5.15.1`).
* README section "TLS, mutual TLS and certificates": modes, loading PEMs from files, a test PKI with openssl,
  channel defaults, security notes and troubleshooting.

### Tests

* `ClientConfigTest` and `GrpcChannelsTest`: real TLS handshakes against a loopback Netty server with a PKI
  generated at test time (BouncyCastle, test scope only; no key is committed) - TLS with a custom CA, mutual
  TLS, CRLF PEMs, IPv6 `[::1]`, empty identity = plain TLS; missing client certificate, client from an
  unrelated CA and wrong CA end in `UNAVAILABLE`; half pair, plaintext with identity, insecure warning and
  redaction edge cases. The 100 % JaCoCo gate now also covers `com/ondewo/vtsi/channel/**`.
* `ReleaseNotesTest` pins the `RELEASE.md` heading spelling and the `*****` separator the GitHub release
  body is sliced by, and that the current version has non-empty notes.

## Release ONDEWO VTSI Java Client 8.7.0

### New Features

* Initial release of the ONDEWO VTSI (Virtual Telephony Server Interface) gRPC client for Java. The library
  is generated from the protobuf definitions of [ondewo-vtsi-api](https://github.com/ondewo/ondewo-vtsi-api)
  by the `ondewo-java-proto-compiler` image of the
  [ONDEWO proto compiler](https://github.com/ondewo/ondewo-proto-compiler) release
  `5.15.1`: `protoc --java_out` for the message classes, `protoc-gen-grpc-java` for the
  service stubs, and a rendered `pom.xml` that pins the gRPC, protobuf and
  `proto-google-common-protos` versions the stubs were generated against. The packaged artifact is
  `com.ondewo:ondewo-vtsi-client-java`, compiled with `maven.compiler.release=11`, and ships a
  sources jar alongside the binary jar.
* `make build` regenerates the whole client from the pinned submodules - api protos and proto
  compiler - and `make test` verifies that every `.proto` produced java code before running
  `mvn verify`: the JUnit 5 suite over the **committed** stubs (432 generated java files, 23 gRPC
  services) plus the JaCoCo gate. Both run in CI on JDK 11 and JDK 21, unconditionally - a
  missing or truncated client turns the run red instead of skipping a step.
* Adds the one hand-written class of this client, `com/ondewo/vtsi/auth/BearerToken.java`, which wraps the
  `authorization: Bearer <token>` header every ONDEWO server expects and decorates any generated
  stub with it. Coverage is measured over the hand-written sources only and the build fails below
  100% instruction, branch and method coverage.
